# **4. Simulation scenarios**

I recommend six scenarios. Each one will have a generator, sample events, detection logic, dashboard alerts, and an investigation report.

| Scenario                     | Detection objective                     | MITRE ATT&CK |
| ---------------------------- | --------------------------------------- | ------------ |
| SSH brute force              | Repeated failed authentication          | T1110        |
| Suspicious login             | Unusual login behavior                  | T1078        |
| Port scanning                | Reconnaissance activity                 | T1046        |
| Privilege escalation         | Suspicious sudo activity                | T1548        |
| File modification            | Unexpected sensitive-file changes       | T1565.001    |
| Suspicious process execution | Potentially malicious command execution | T1059        |

These mappings are starting points. We'll verify the precise technique and sub-technique against the behavior simulated.

**Realism requirement:** Events should have timestamps, source IPs, hostnames, usernames, event IDs, and realistic relationships. We should also include normal background activity so the detection engine has to distinguish ordinary behavior from suspicious behavior.

For example, the SSH scenario should not simply generate an alert whenever a failed login occurs.

It should:

- Track failed attempts by source IP and target account.
- Count attempts within a defined time window.
- Identify threshold violations.
- Generate an alert with supporting event evidence.
- Avoid generating duplicate alerts for every failed attempt.

# **9. How we'll prove the project actually works**

This is important. A portfolio project should demonstrate results, not just look attractive.

We'll implement these validation checks:

- A known brute-force pattern generates an alert.
- A single failed login does not trigger a brute-force alert.
- Normal login activity does not generate unnecessary alerts.
- Detection alerts contain supporting log evidence.
- Multiple events are correlated correctly.
- MITRE ATT&CK mappings are documented.
- Incident reports match the actual generated events.
- The dashboard works from a fresh installation.

We'll use reproducible synthetic data with clearly identified simulation timestamps and sources. No fabricated claims of real attacks or live security monitoring.
