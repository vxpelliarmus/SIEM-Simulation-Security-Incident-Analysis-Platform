# SOC-SIM Limitations & Educational Scope

This document provides transparent disclosure regarding the operational boundaries, technical trade-offs, and design limitations of SOC-SIM.

---

## 1. Simulation Scope & Synthetic Telemetry

- **Educational Purpose**: SOC-SIM is developed strictly for educational demonstration, portfolio presentation, and SOC analyst training. It is not an enterprise SIEM product or a production replacement for systems like Wazuh, Splunk, Elastic Security, or Microsoft Sentinel.
- **Synthetic Telemetry**: All security events and network traffic generated by SOC-SIM are synthetic. No actual network attacks, port scans against external infrastructure, or malicious exploitation routines are executed.
- **Reserved IP Allocations**: All external source IPs utilize RFC 5737 documentation blocks (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`) and RFC 1918 private subnets (`10.0.0.0/8`, `192.168.0.0/16`).

---

## 2. Storage & Scaling Boundaries

- **SQLite Backend**: SOC-SIM uses SQLite with Write-Ahead Logging (WAL) enabled for local single-node persistence.
- **Scalability Limit**: SQLite performs well for simulations with tens of thousands of records, but is not designed for distributed enterprise ingestion rates (e.g. 50,000+ events per second). Production SIEM architectures utilize distributed columnar stores (ClickHouse), search clusters (Elasticsearch/OpenSearch), or message brokers (Apache Kafka).

---

## 3. Detection Architecture & Sigma Representation

- **Custom Python Detection Engine**: To eliminate external dependencies and allow offline execution on a standard Kali Linux laptop, detection logic is executed via Python scripts (`detection/engine.py` and `detection/correlation.py`).
- **Sigma Rules**: The Sigma rules provided in `sigma_rules/` are standardized specifications compatible with the Sigma standard. They are included to demonstrate professional detection engineering documentation and rule portability, but are not directly compiled through `pySigma` at runtime.

---

## 4. Host Telemetry vs. Kernel Instrumentation

- **Log Generation**: In a live enterprise deployment, host events are collected via kernel instrumentation frameworks such as Linux `auditd`, eBPF, Windows Event Log, or osquery.
- **Simulation Modeling**: In SOC-SIM, events are synthetically modeled as structured JSON records to replicate the fields and semantics produced by audit daemons and network flow collectors without modifying the host system's configuration.
